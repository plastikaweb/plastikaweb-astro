# Lens: i18n — three locales and localized routes

Locales: Catalan (`ca`), Spanish (`es`), English (`en`). Reference: requirements §5 (with D-01, D-02, D-11) and `docs/i18n.md` once T-31 writes it.

## Already mechanical (input, not work)

Once T-31 lands: each locale dictionary `satisfies` the same key type, so a missing key fails `astro check`; the empty-string check rejects blank values. Don't recompute key parity by eye.

## Judgement checks

1. **No single-language copy.** Every user-visible string and accessible name in the touched templates comes from the dictionaries or from localized content, never a literal in one language (attributes too: `alt`, `aria-label`, `title`, `placeholder`).
2. **Language sanity.** `ca` in Catalan, `es` in Spanish, `en` in English; no copy pasted across locales as a placeholder; the same term for the same concept across the file and across pages.
3. **Length.** Catalan and Spanish run ~30% longer: nothing in the touched markup or CSS assumes the English length (fixed widths, single-line truncation of labels, buttons sized to the English text).
4. **Routes and links.** Internal links go through the localized-path helper, not hardcoded `/en/...`; the language selector links to the same page in the other locale, or to the other locale's blog listing for a post that doesn't exist there (D-11).
5. **Missing translations** (D-11). Pages, case studies, site settings and UI strings fail the build when a locale is missing; blog posts and personal entries appear only in the locales where they exist (listings, feeds, sitemaps, `hreflang`). No fallback-language content.
6. **Formatting.** Dates, numbers and reading time formatted per locale (`Intl`), not by string concatenation.
7. **Interpolation and plurals.** Every placeholder exists in the three locales and matches what the code passes; copy that varies by count handles it in all three.
8. **Deleted UI.** Keys only that UI used are removed from all three dictionaries.
